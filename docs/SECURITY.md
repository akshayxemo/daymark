# Security review

This records the controls implemented in the code and how they were verified. To report a vulnerability, see [../SECURITY.md](../SECURITY.md). This is an engineering self-review, not an independent audit.

| Area                      | Control                                                                                                                                                               | Where                                              | Verified by                                                                           |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------- | ------------------------------------------------------------------------------------- |
| Authentication            | Better Auth email + password, scrypt password hashing, 10–128 character passwords                                                                                     | `src/server/auth/auth.ts`                          | `tests/integration/auth.test.ts`, e2e                                                 |
| Sessions                  | Database-backed, HTTP-only cookie `daymark.session_token` (`__Secure-` prefix and `Secure` on https), 30-day expiry with daily refresh, 60-second signed cookie cache | `auth.ts`                                          | auth tests (expired and invalid sessions rejected)                                    |
| Email verification        | Required by default before sign-in; links expire after 24 h                                                                                                           | `auth.ts`                                          | auth tests, e2e through Mailpit                                                       |
| Password reset            | One-hour token, revokes all sessions on reset; response does not reveal whether the email exists                                                                      | `auth.ts`, `forms.tsx`                             | auth tests, e2e                                                                       |
| Account deletion          | Password + emailed confirmation link; cascades all user data                                                                                                          | `auth.ts`, schema `onDelete: cascade`              | auth test checks rows are gone                                                        |
| Registration control      | `open` / `invite` / `disabled`, single-user mode; first account always allowed; invitations single-use, optional email binding, expiry                                | `registration.ts`, `before` hook                   | auth tests                                                                            |

## Known limitations

- No content security policy header yet. Next.js inline runtime scripts need nonces, which requires dynamic rendering of every page; planned with the next hardening pass.
- No multi-factor authentication; Better Auth's two-factor plugin is the intended route.
- Rate limits are per IP. Behind a proxy that does not forward `X-Forwarded-For`, all clients share one bucket.
- The publisher/admin analytics dashboard is not implemented, so no aggregate usage data is collected at all.
